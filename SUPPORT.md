 # Support

 ## Documentation first

 Before opening a support request, please check:

 - `README.md`
 - `deployment/README.md`
 - `RELEASE_CHECKLIST.md`
 - `SECURITY.md`

 ## Where to ask for help

 Use GitHub Issues for:

 - reproducible bugs
 - documentation gaps
 - setup problems with clear reproduction details
 - feature requests

 For responsible security disclosure, use the private process described in
 `SECURITY.md`.

 ## What to include

 When asking for help, include:

 - operating system
 - Python version
 - whether you are using local runtime or Docker/Kubernetes
 - relevant environment variables or config sections (redacted as needed)
 - exact commands run
 - logs or stack traces
 - whether Postgres / Redis / Neo4j were reachable

 ## Response expectations

 As an open-source project, support is provided on a best-effort basis.
 Clear, minimal, reproducible reports are far more likely to receive fast help.
